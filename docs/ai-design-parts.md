# 窓・家具の仕様

`/create` の手動編集とAI編集で共通の部品定義を使う。

| 部品 | 対応範囲 |
| --- | --- |
| 窓 | 背面中央の四角、丸・楕円。壁から実際に差分形状を作る |
| 従来の棚 | 1個。追加家具と併用できる |
| 追加家具 | 最大6個。棚、4脚テーブル、四角い台座、丸・楕円の台座 |
| 編集 | ID単位の追加・更新・削除、選択部品の色・寸法変更、取り消し |

丸形状は64分割。テーブルは天板と4脚を接続した立体で、天板を下にして印刷する。独立した家具も3MF・GLB・USDZに含める。

## データと検証

- `document.ts` は型・寸法・色・位置・ID・個数を限定する。旧v1ファイルにない窓形状・家具配列は既定値で補う。新しい形式を古いアプリで読むことは保証しない。
- `ai-contract.ts` はID指定のupsert/removeで家具を編集する。別の家具を保持し、重複ID・競合操作・未知の項目・範囲超過を拒否する。
- おうちの外へのはみ出しと家具同士の重なりを検査する。衝突は床上の外接矩形で判定する。丸台座の隅やテーブルの下の空間も占有とみなす。
- 手動編集で不正な配置になった場合は問題を表示し、印刷出力を止める。AI案は検証・修正後に元のrevisionと照合して適用する。

固定家具は床置きで、回転配置・積み重ね・入れ子・扉・階段用テンプレートはない。自由形状は [別の実行系](freeform-modelling.md) で扱う。ぬいとの干渉、脚の強度、転倒、造形成功は保証しない。

## テストとサンプル

`tests/design-parts.test.ts` は旧形式互換、窓の体積、家具の閉じたメッシュ・印刷方向・出力、ID保持、衝突拒否を検査する。`tests/e2e/design-parts.spec.ts` は手動配置と模擬AIによる追加・選択編集を扱う。

[家具付きのおうち](examples/furnished-house.oshinest.json) を設計ファイルとして読み込める。実モデル評価CLIには `--parts` を指定する。接続方法とAPI呼出の予算は [AIチャット](design-ai-chat.md) を参照。
