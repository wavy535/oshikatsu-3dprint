# AIで制作できる形・部品の拡張

2026-09-28。目的は、自然言語から複数の家具を置いたおうちを制作し、検証エラーを使って修正できる範囲を広げること。

## 今回の変更

| 操作 | 以前 | 今回 |
|---|---|---|
| 窓 | 四角のみ | 四角、丸・楕円 |
| 家具 | 棚1個 | 従来の棚を保持し、追加家具6個まで |
| 追加家具の種類 | 未対応 | 棚、4脚テーブル、四角い台座、丸・楕円の台座 |
| 家具編集 | 固定の棚の寸法変更 | ID単位の追加・更新・削除、選択家具への指示 |
| 配置検査 | 棚と壁の範囲 | 追加家具と壁、他の家具・従来の棚との重なり |
| 修正ループ | 寸法・印刷範囲で1回再提案 | 新しい配置検査も同じループへ接続 |

これは表現できる設計と検証範囲の比較。実モデルの成功率が改善したという結果ではない。

例：「窓を直径60mmの丸窓にして」「奥に小さな棚を2つ並べて」「選んでいるテーブルだけ赤くして」。追加家具は手動でも作成・寸法変更・削除できる。AIによる変更は従来どおりUndoの1操作で戻せる。

## 実装と判断

- `document.ts`: 家具は型・寸法・色・位置・IDを限定し6個まで。旧v1ファイルの欠けた窓形状と家具配列には既定値を補い、読み込み時の形状を維持する。古いアプリへの逆方向の互換性はない。
- `parts.ts` / `geometry.ts`: 全部品を既存Manifold WASMで生成する。丸形状は64分割で、窓は壁からの実際の差分形状。テーブルは天板と4脚の接続した立体で、天板を下にして印刷する。独立した家具も3MF・GLB・USDZに含める。
- `ai-contract.ts`: 家具配列を丸ごと上書きさせず、ID指定のupsert/removeを使う。別の家具は保持し、重複・競合操作、未知の項目、造形範囲超過を拒否する。
- `ai/skill.ts`: 対応部品、座標、配置例、選択対象、依頼外の変更禁止を追加。自由コード生成は導入しない。
- `ai/harness.ts`: 現在の検査結果に印刷範囲も加える。失敗した提案は適用せず、検証エラーと提案をデータとして返して元の設計から1回だけ再生成する。家具名を含む検証エラーをdeveloper指示へ昇格させない。最大2呼び出し・45秒、既存の利用枠は維持。
- ブラウザは提案を再検証し、実WASMメッシュ検査後、元のrevisionと一致するときだけ適用する。途中の手動変更を上書きしない。再提案があったことを会話に表示する。

Structured Outputsの全項目必須・追加プロパティ禁止を検査するテストも追加。[OpenAI公式仕様](https://developers.openai.com/api/docs/guides/structured-outputs)に基づく。新しいモデル・外部サービス・依存パッケージは追加していない。

## 再開時の検証

ネットワーク・ローカルサーバー・Git書き込みが利用可能な環境で実施する。

```sh
npm test
npm run typecheck
npm run lint
npm run build
npx wrangler dev --config dist/server/wrangler.json --persist-to .wrangler/state --port 3000
# 別ターミナル
npx playwright test tests/e2e/design.spec.ts tests/e2e/design-chat.spec.ts tests/e2e/design-parts.spec.ts
```

実モデル用の代表8ケースを追加した（丸窓、棚2個、テーブル、丸台座、選択編集、1個削除、重なり修正、未対応形状への回答）。有料評価を実行する際は、キーを表示せず次を実行する。最大16呼び出しで8ケースの各1回の修正まで収まる。

```sh
node --experimental-strip-types scripts/evaluate-design-ai.ts --live --parts --max-calls=16
```

結果は `/tmp/oshinest-ai-evaluation-parts.json`。既存の基本評価も、丸窓を「未対応」とする期待値から更新した。過去の評価JSONは変更していない。

## 残る形状上の制限

床置きのみで、自由曲面・階段・扉・回転配置・積み重ね・入れ子は未対応。衝突は床上の外接矩形による保守的な判定のため、丸い台座の隅やテーブルの下も占有とみなす。ぬいとの干渉、接合・脚の強度、転倒、実機AR、造形成功は保証しない。手動で不正な配置になった場合は元の編集方式どおりプレビューに問題を表示し、3MF出力を止める。

自由形状コード、画像入力、実メッシュ修正の追加仕様・検証状況は [自由形状のAIモデリング](freeform-modelling.md) を参照。
