# AIとの会話によるおうち編集

追記：丸・楕円の窓、複数家具と検証・修正の拡張は [AI制作能力の拡張](ai-design-parts.md) を参照。以下は初回実装時の記録です。

2026-09-28。`feat/ai-house-chat` で実装。先行する手動エディタはPR #6でマージ・配備済みだが、このAI機能は別PRでレビューし、マージ・公開はまだ行わない。

## 利用者の操作

`/create` の「制作チャット」へ「幅を2cm広げて」「右奥に棚を置いて」と送ると、現在の設計から変更案を生成し、検査後に自動反映する。続けて会話でき、既存の取り消し・やり直し・端末保存・3MF出力を使える。手動編集は匿名でも使え、AI送信には一般会員ログインが必要。

APIは現在の設計、選択部品、直近8メッセージを受け取る。編集後の履歴には実際に適用した差分を渡す。設計を変更しない相談では、AIの返答も履歴に含めて提案や質問の続きを話せるようにする。現在の設計が正本で、手動編集や取り消しを過去の会話で巻き戻さない。会話はタブ内のメモリだけに保持し、再読み込みで消える。会話のクリアは設計を消さない。

## ハーネスとモデリング指示

- `src/lib/design/ai/skill.ts`: 単位、部品の対応範囲、座標、寸法制約、変更範囲、依頼外の変更禁止を記載したアプリ内のモデリング指示。開発エージェント用のインストール型スキルではない。
- `ai-contract.ts`: 編集可能なパスと値の型を限定。プリンタの造形範囲・版の変更、任意コードや任意プロパティへのアクセスは禁止。実メッシュと一致する部品の外接寸法も計算する。
- `ai/harness.ts`: OpenAI Responses APIのStructured Outputs。1回提案し、寸法検査に失敗した場合だけ元の設計に対して1回修正する。拒否・不完全応答・接続失敗を扱い、最大2 API呼び出し・45秒で終了する。`store:false`。
- クライアントは受け取った差分を再検証し、さらに既存WASM Workerで実メッシュを生成して検査する。元のrevisionと一致する場合だけ、履歴の1操作として反映。応答中の手動編集、取消、ファイル読込、再読み込み、中止を上書きしない。

自由形状生成、丸窓、扉、階段、棚の複数配置は対象外。ぬいと棚の干渉・強度・造形成功を保証しない。寸法検査は通っても意味的に誤った変更を生成する可能性があるため、変更差分を画面に出し、取り消せるようにしている。

## 接続と利用制限

キーはサーバーの `OPENAI_API_KEY` だけで読む。ブラウザ・モデル入力・Gitに含めない。ローカルでは `.dev.vars` に設定する。`.env` が裸のキーでも評価CLIは読めるが、Workerは `.dev.vars` が必要。設定ファイルはGit対象外で、値をログに出さない。

```bash
npm run db:migrate
npm run cf:types
npm run dev
```

本番へ配備する段階では、`0009_ai_design_usage.sql` をリモートD1へ適用し、既存アカウントのWorker `oshinest` に `OPENAI_API_KEY` をsecret登録してからWebを配備する。今回、リモートのDB・secret・配備は変更していない。secret登録時にはキーをコマンド引数やPRへ記載せず、標準入力を使う。

`POST /api/design/chat` は同一origin、JSON、実セッションを検証する。指示1000文字・画像込み本文1MiB・履歴8件の上限。D1の単一条件付きINSERTで、UTC日付ごとにユーザー30回・サービス全体300回、同じユーザーの送信間隔8秒を制限する。失敗・中止も枠を消費する。枠は最大2回分のAPI処理を許可するもので、課金額そのものの上限ではない。

利用枠テーブルにはID・会員ID・時刻だけを保存し、予約時に48時間より古い記録を削除する。指示や設計をD1に保存しない。OpenAI側には指示・設計・会話を送信することを画面に明示する。`store:false` はOpenAI側のすべてのログ保持を無効化する保証ではない。

## 実モデルの評価

初回は同じ8ケースで GPT-4.1 mini と GPT-5 mini を比較した。GPT-5 miniは `reasoning.effort=minimal`。固定の日本語指示、現在の設計と会話履歴、構造化差分、サーバー検査、実WASM形状生成を使用した。各ケース1回であり、統計的な品質保証ではない。

| モデル | 条件を満たしたケース | 中央値（API・検査込み） | トークンからの費用概算 |
| --- | ---: | ---: | ---: |
| GPT-4.1 mini | 8/8 | 2,028ms | $0.00638 |
| GPT-5 mini | 7/8 | 1,372ms | $0.00532 |

GPT-5 miniは棚の右端位置を2mm誤り、過去の依頼に引きずられる説明もあった。GPT-4.1 miniを初期モデルに採用。造形範囲を超える依頼は、両モデルとも1回の修正後に変更なしとして回答した。生の構造化結果は [比較記録](evaluations/design-ai-model-comparison.json)。価格は [OpenAI公式料金](https://developers.openai.com/api/docs/pricing) に基づく標準入力・出力の上限側概算で、キャッシュ割引は未算入。

追加4ケースでは、GPT-4.1 miniも幅を縮める際に依頼外の奥行きを変更した（3/4成功）。指示に寸法連動の具体例を追加し、会話のコンテキストをモデルの説明文から実際の変更差分へ置換した。同じ4ケースを再実行して4/4成功。改善前後の入力履歴の構成も変更しているため、モデル単体の性能改善とは扱わない。[修正前](evaluations/design-ai-extra-before.json) / [修正後](evaluations/design-ai-extra-after.json)。

評価CLIのAPI呼び出しは合計26回（修正呼び出しを含む）。別にローカルブラウザから実APIを1回呼び、ログイン→送信→幅190→210mm→取り消し190mmを確認した。合計27回で、今回の上限30回以内。全リクエストの保守的な費用枠は1回$0.05としても$1.35以下で、予算$5以内。CLIの計測可能なトークン使用量は各記録に残した。

再現する場合は明示的に有料実行を選ぶ。各実行の呼び出し上限は30回（必要ならさらに小さくできる）、最大出力2000トークン、リクエスト64KiBまで。評価スクリプトは毎回の実行単位で上限を数えるので、繰り返す場合の合算予算は別途管理する。

```bash
node --experimental-strip-types scripts/evaluate-design-ai.ts --live
node --experimental-strip-types scripts/evaluate-design-ai.ts --live --extra --max-calls=7
```

## 制作チャットのUI（2026-09-28）

スマホではチャットを先に表示し、PCではプレビューと横並びにする。会話欄はスクロール可能、入力欄はその下に常時配置する。ユーザーの発言は送信直後に吹き出しとして表示し、AIの返答と実際に適用した変更は分けて表示する。画像添付、処理中の表示、停止、エラー時の入力復元に対応する。

Enterで送信、Shift+Enterで改行。日本語IMEの確定中は送信しない。失敗・中止した発言は未完了として残すが、次回のAPI履歴には含めない。会話のクリアは設計に影響せず、次の送信まで「会話を戻す」で取り消せる。

相談だけの依頼にはchanges=[]で返すよう指示する。生成品質や3Dエンジンの機能範囲はこのUI変更では拡大していない。
