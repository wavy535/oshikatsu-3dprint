# 制作フローの判断基準

主な利用者はCADに慣れていない、ぬいのおうちや家具を作りたい人。今回の中心は「AIで作る・直す → 形を見て調整 → ARで確認 → 保存」。作品を探す機能は残すが、初回の入口をマーケットから制作へ変更した。

## 画面を増やさない

- `/` は `/create` へ転送する。従来の説明中心のトップを統合し、すぐ編集を始められるようにした。
- 主な移動先は「つくる・さがす・マイページ」の3つ。マイぬい・カートはマイページから利用できる。会員、作品、注文、運営用のデータやルートは削除しない。
- 制作画面ではAI・手動調整・完成後の操作だけを切り替える。会話は切り替えで消さず、処理中のAI応答にも既存のrevision検査を適用する。
- スマホは上にプレビュー、下に操作。PCは左にプレビュー、右に操作。設定や会話のスクロールでプレビューを見失わないよう、それぞれの領域内をスクロールする。
- 数値は有効な値を入力した時点で反映する。消去中や範囲外の途中値では設計を壊さず、入力終了時に検証・復元する。

## 完成後の操作

「完成・ARへ」を常に表示する。完成側は「飾る場所で確認」「作品を残す」の順にし、ARと端末保存を主要操作にする。印刷・GLB・USDZ・検査結果は詳細を開いたときに表示する。製造エラーで印刷ができなくても、AR用データは出力できる。

保存は端末内1件。JSONで別の端末に持ち出せる。クラウド保存、注文・出品への自動連携があるようには見せない。AR非対応の端末では3D表示になる。実機AR・実プリントの精度と強度は自動検査の対象外。

壁と屋根の隙間は説明だけでは解決しなかったため、前後の三角壁を追加する操作を実装した。寸法は屋根に追従し、手動とAIは同じ設計項目を変更する。以前の設計を読み込んでも形を変えないよう、旧ファイルは隙間を開けた状態として扱う。

## コードの境界

`use-design-session.ts` は設計履歴・Worker・適用前の形状検査を担当する。`use-design-files.ts` は端末保存、ファイル読込、ダウンロードとAR用URLの寿命を担当する。画面はプレビュー、手動操作、完成後の操作に分け、`house-editor.tsx` で配置と選択状態を接続する。造形コアは引き続きReactやDOMに依存しない。

## 表現と検証

白地・濃い文字・罫線を基本に、既存の青を主要操作へ使う。初期画面の説明と繰り返しの案内を減らし、変更差分や利用条件は必要に応じて開く。装飾用のフォントやアニメーションは追加しない。

320px幅、入力中の即時反映、プレビューの画面内表示、AIの遅延・中止、取消、保存復元、出力をPlaywrightで確認する。AIの応答は模擬するため、モデルの理解力や見た目の品質を証明するものではない。実機ARとユーザビリティ調査は別途必要。

2026-11-07の確認結果：Node 24、Chromium、ローカルのCloudflare Workerで制作・モバイル・可読性・CSSのE2E 34件が成功。Vitestは371件成功、外部サービスを必要とする7件はskip。型検査・lint・vinext互換性検査・本番ビルドも成功した。

初期設計・会話なし・390×844pxの同条件で、画面全体の高さは4,165pxから844px、mainの表示文字数は1,017字から170字になった。変更後はプレビューと入力欄を同時に表示でき、320×568pxでも横のはみ出しがないことを確認した。この比較は配置と初期表示の比較であり、利用者が制作を完了できるかを調べたものではない。
