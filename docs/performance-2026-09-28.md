# 公開環境のLCP調査・改善（2026-09-28）

## 対象と条件

`https://oshinest.yumaboda-official.workers.dev` の `/`、`/works`、`/login` を、未ログインで計測した。変更前は99f2700（Worker version `7b18ab57-5a12-430d-b7a2-a1a56e6fc7f5`）。

- PlaywrightのChromium、390×844px、CPU 4倍減速。
- CDP通信制限: 下り1.6Mbps / 上り750Kbps / latency 150ms。
- 各回新しいブラウザコンテキスト、ブラウザキャッシュ無効、Cookieなし。
- 各ルートのWorkerを事前に1回呼び出した後、3回ずつ測定。
- Chrome DevTools MCPはChrome実行ファイルがなく起動できず、既存PlaywrightからCDPとPerformanceObserverを使用した。
- 同じ計測スクリプト・端末条件で変更前後を比較。ネットワーク経路・Workerの配置・負荷の変動は含む。

これはラボ計測であり、実利用者の75パーセンタイルやCrUX値ではない。会員ページの本番LCP、作品が大量に登録された状態の画像性能は今回の数値に含まない。

トップのHTMLは40877 → 32654B、DOM要素は201 → 157、観測時間内のリソース要求数中央値は19 → 13になった。JS本体のdecoded sizeは約541 → 538KBで、JSの大幅な削減ではない。ネットワークの実転送量とdecoded sizeは区別する。

[全18試行の数値](performance/lcp-2026-09-28.json)に条件・ブラウザバージョン・LCP要素・エラーを保存した。JS量はmodulepreloadで取得されたものも含めてリソースURLから集計している。表示内容やネットワーク経路が変われば数値も変わるため、実利用環境での継続計測は別途必要。

## 原因と対処

[web.devのLCP分解](https://web.dev/articles/optimize-lcp)に沿って、TTFB、リソース取得、描画までの待ち時間を確認した。変更前のトップの中央値はLCP 2384ms / TTFB 1975ms。作品一覧はLCP 2640ms / TTFB 2262ms。最大の待ちはHTML応答前にあった。

コードでは `getOptionalUser()` が、セッションCookieのない訪問者でも `getAuth().api.getSession()` を呼んでいた。Better Auth 1.7.3は初期化時にスキーマを照合する。リクエストごとに作成するD1アダプターは65テーブルの `pragma_table_info` をバッチ照会するため、匿名のトップ表示にも不要なDB往復が発生していた。

Cookieなしの場合だけ匿名コンテキストを返し、この初期化を省いた。Cookieありの場合は従来どおり署名・有効期限・DBセッションをBetter Authで検証する。Cookieの存在を認証成功とは扱わない。[Better Authの注意事項](https://better-auth.com/docs/integrations/next#auth-protection)に従い、保護ページのガードも維持した。認証オブジェクトのリクエスト間共有、スキーマ検証の無効化、個人情報の共有キャッシュは導入していない。

初回表示後、ナビゲーションの自動prefetchが会員ページへのアクセス→ログインへのリダイレクト→追加JS取得を発生させていた。会員・認証リンクと多数の絞り込みリンクでprefetchを止め、選択時に取得するようにした。これはLCP後の通信も減らすための変更であり、LCP改善量に個別の効果は割り当てない。

デザイン整理で宣伝用のイラスト、繰り返しカード、アイコンを削減した。旧トップのLCP要素は2778BのSVGだったが、画像自体は大きくない。画像圧縮を主因対策として扱っていない。画像の削除はUIの目的を見直した結果である。

## 再現

```bash
PERF_BASE_URL=https://oshinest.yumaboda-official.workers.dev \
  npm run perf:frontend -- / /works /login
```

ローカルでは本番ビルドをWranglerで起動して `PERF_BASE_URL=http://localhost:3000` を指定する。Vite開発サーバーの値は比較に使わない。各試行のLCP要素、TTFB、FCP、CLS、転送量、リソース一覧、long task、ブラウザエラーをJSONに出力する。

## 回帰確認

匿名訪問が認証APIを初期化しないこと、通常・Secure両Cookieが必ずサーバー検証を通ること、偽造・失効Cookieで保護ページに入れないことをテスト。会員登録・ログイン・権限・購入・ファイル・ARは既存テストで確認した。

型チェック・lint・Vitest 266件（46ファイル）・本番ビルド・Wrangler dry runが成功。本番ビルドのブラウザ14件が成功し、今回の公開条件で無効なゲスト2件はスキップ。公開先でもUI試験3件、ヘルスチェック、公開ページ200、会員・運営ページの未認証リダイレクト、非公開ファイル404を確認した。
