# 自由形状のAIモデリング

装飾の多い椅子やキャラクターの装備を、固定家具テンプレートの追加ではなく、AIが輪郭・断面・曲線を定義するコードで作るための実装。既存の家具とCSG部品も維持する。

## 利用方法

1. `/create` のチャットで「単体で、高さ100mmの曲がった脚と唐草飾りの椅子を作って」のように依頼する。
2. 必要ならJPEG/PNGを2枚まで添付する。ブラウザで最大1024px・JPEG 300KiB以下へ再描画し、画素をOpenAIへ送る。画像は現在のチャット状態にのみ保持し、設計JSON・会話テキストに入れない。添付は削除するまで次の送信にも含まれる。
3. 「背もたれの装飾を太くして」などで、同じモデルIDのコードを更新する。プレビューと寸法を確認する。
4. 単体の家具・装備モードでは床・壁・屋根を出力しない。元のおうちの設定は保持される。家具・部品は引き続き残る。
5. 設計JSONを保存し、3MF ZIP / GLB / AR用データを書き出す。3MFは部品ごと。試し刷りは別途必要。

すぐ読み込める手書きの検証サンプル:

- [装飾付きの椅子](examples/decorated-chair.oshinest.json): 複数断面から作る曲がった脚、任意輪郭の背もたれ、5個の渦巻き装飾。
- [湾曲した装甲](examples/curved-armor.oshinest.json): 幅と曲率が変わる断面、表面に沿う波状の紋様。

これらはAI生成の品質を示す作例ではなく、実行系と編集・出力を検証するための固定データ。

## 方式と採用理由

モデルには `program.upsert` で `{id,name,x,y,color,size,source}` を返させる。sourceは制限したJavaScript構文で、`let/const`・`for`・配列・数値演算・少数のMath関数を使用できる。関数定義・任意プロパティ・import・ネットワークは使用できない。Acornで構文木へ変換し、専用インタプリタが評価する。`eval` / `Function` / 生成JSモジュールは使わない。

モデリングAPIは `extrude`（任意輪郭）、`revolve`、`loft`（断面をつなぐ曲面）、`tube`（曲線に沿った丸い装飾）、`mesh`（任意三角形メッシュ）、基本立体、変換、集合演算。反復装飾はループで表す。頂点列だけをモデルに大量出力させる方式より、繰り返しや形の変更を短いコードで表現できるため採用した。実モデルの品質比較は未実施。

コードは既存のブラウザWorker内で評価し、Manifold WASMで立体化する。同じ処理をNode CLIから呼べる。実行系へ渡す値は数値・真偽値・null・配列のみ。WASMオブジェクトをコードに直接公開せず、呼べるAPIを名前で限定する。

- ソース12KB、AST深さ64、評価10万ステップ、配列割当3万要素。
- 最大3モデル、外寸上限各方向200mm。sizeは上限申告であり、実寸が超えたら拒否する。
- 立体ハンドル384、各立体3万三角形、累計60万三角形。Workerには既存の20秒タイムアウトがある。
- loftは同じ頂点数の断面をつなぐ。断面はXY上の凸形・星形で、Z昇順を想定。NURBS編集やスカルプトではない。
- tubeはサンプル点を球の凸包でつなぐ近似。全体は1つの連結した立体にする。
- 設計ファイル上限を128KiBへ拡張。旧設計は `programs:[]`, `scene:"house"` を補って読める。

生成時はサーバーが構造・構文・宣言寸法を検査し、ブラウザが実際のメッシュを検査する。空・分離・実寸超過・モデリングコードのエラーを、失敗した提案とともに、残りのモデル呼出予算内でOpenAIへ戻す。修正が通るまで元の設計を変更しない。手動編集や取消が先に行われたら適用しない。

通常リクエスト内のサーバー修正は最大1回、ブラウザからの形状修正リクエストは各1モデル呼出。ユーザー操作あたり合計最大3モデル呼出、最大3回のアプリ利用枠を消費する。後者は8秒の利用間隔を守る。認証・Origin検査・利用上限は維持する。

## リリース前の追加検証（2026-09-28）

環境制約の解除後、全ユニット／統合テストを実施（349件通過、7件skip）。既存のブラウザE2E12件も通過した。自由形状と画像添付のE2Eも2件追加して通過し、合計14件。実ブラウザWorkerでの生成・画像送信・変更・取り消し・出力を確認し、椅子の描画もスクリーンショットで目視確認した（AI応答は模擬）。

実OpenAIの評価は合計12呼出で終了。gpt-4.1-miniの最初の4ケースは0件成功。未対応の関数定義・map/reduce・スプレッドを出力し、修正後も構文を直せないケースや生成を断念するケースがあった。gpt-5-miniも2呼出では椅子の生成完了に至らず、重なる余分な座面部品を追加するなどの問題があった。API接続とStructured Outputs自体は動作している。

対策として検証済みの椅子・装甲コードを指示に追加し、APIの引数数も厳密に検査するよう変更。既定モデルはgpt-4.1-miniを維持した。変更後の生成成功率、画像からの形状再現品質は未確認であり、実行系のテスト成功と混同しない。追加の有料評価は今回の12呼出上限で打ち切った。

## 生成エラーからの回復（2026-09-29）

- `union`は2〜16個の立体を受け取り、全てを順に結合する。他のAPIは固定の引数数を維持する。余分な引数を無視しない。
- AST検査で関数名・引数数・未対応構文／メソッドを実行前に確認。診断には行番号と正しいAPI仕様を含め、API実行中の例外にも行番号を付ける。
- 1操作あたり最大3モデル呼出、全体140秒。最初のサーバー内修正もreply.attemptsで予算から差し引く。ブラウザからの各修正要求はサーバー側で1モデル呼出のみ。各HTTP要求は従来どおり利用枠を消費し、8秒の送信間隔を維持する。
- エラーと該当する提案、修正方針を同時に渡す。装飾の削除や別の形への置換が必要なら、勝手に適用せず相談するよう指示する。
- 同じ提案（正常に構文解析できるソースはコメント・空白・AST位置情報を除外）、または同じ診断が2回続く場合は打ち切る。HTTP・認証・利用制限エラーを無条件で再送しない。
- 成功するまで元の設計は変更せず、取消・手動編集の後に古い結果を適用しない。
- 最後の内部例外をチャットへ表示しない。作成未完了と元モデルの保持を説明し、「もう一度試す」「作り方を相談する」を表示する。相談を選ぶと元の依頼を含む相談文を入力欄に戻し、勝手に送信しない。

最終診断は開発者向けにブラウザのconsoleへ最大1000文字で記録し、画面には表示しない。コード全文・画像は記録しない。

検証: 3項unionの実体積、実行前検査、異なるエラー2回から3回目での成功、サーバー修正を含む合計上限、同じコードの再提出停止を自動テストで検証。既存の取消・手動編集との競合テストも維持する。実モデルの生成成功率の改善は未測定。
