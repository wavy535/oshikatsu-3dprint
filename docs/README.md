## 更新ルール

- 仕様は現在形で記す。変更時は該当箇所を更新し、「追記」「今回」「以下は以前の記録」を重ねない。
- 決定は「採用内容・理由・制約」を残す。試行順、作業者との会話、コミット・pushの経過はGitやPRで扱う。
- 手順・設定値の説明を複製しない。実装と異なればコードを確認して正本を更新する。
- 計測には対象版・条件・結果・限界を残す。過去の成功件数や配備バージョンを現在の保証として使わない。
- 実装済み、配備済み、実モデルで確認済み、実機で確認済みを区別する。

過去の文書をarchiveとして蓄積しない。現行仕様と判断理由を更新し、過去の経緯はGit履歴で確認する。
