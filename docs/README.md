## 書き方

仕様が変わったら本文を更新する。採用した方式と理由を書き、作業日誌は追記しない。古い文書はGit履歴で確認できるため、archiveには残さない。

処理名や操作を具体的に書く。「境界を守る」なら何を拒否するのか、「確認済み」なら何をどう確かめたのかを示す。同じ説明や注意書きを複数の節に繰り返さず、手順は該当資料へリンクする。

数値、制限、未検証の項目は省略しない。実装済みと配備済みを分け、計測結果には対象版と条件を添える。
